# 🎙️ 发言席位（Speak Queue）

适合**线下讨论、会议投屏**使用的多人发言席位 Web 应用：

- 创建者一键生成 **6 位房间码**，即主持人；
- 参与者用**昵称加入**，自行**申请 / 取消发言**；
- 排队者之间可**协商换位**：发起邀请、对方接受/拒绝，位置原子交换，冲突自动失效；
- 主持人可**拖动排序**、**开始 / 结束发言**、将成员移出队列、**一键清空**；
- **限时发言**：主持人开始发言时可选择 1～30 分钟时长，所有客户端按服务端时间
  同步倒计时，最后 30 秒红色醒目提示；到期服务端自动结束本轮并写入操作记录，
  手动结束 / 撤销 / 切换发言人都会使旧定时任务失效，断线重连后倒计时继续；
- **累计发言配额**：主持人可开启每人 1～30 分钟的累计发言配额，并可随时
  **重置新周期**（全员余额清零、周期标识更新）；服务端按每轮**实际发言时长**
  结算扣减，手动结束与到期回调竞争时只结算一次；余额耗尽**自动结束**当前发言
  且**禁止再次排队**，成员、队列与当前发言区实时展示余额与耗尽状态，
  断线重连后余额连续恢复；
- **队首点名接力**：主持人一键启动后，服务端按队列顺序逐一向成员发出 **20 秒确认**；
  成员点「确认」即从队列移除并开始发言，点「跳过」或超时则移到队尾并自动点名下一人，
  同一轮每人最多被点名一次，全部跳过后自动结束；主持人可随时取消。快照下发
  `callId` / 截止时间 / 本轮已点名成员，确认/跳过同时校验版本与 `callId`，
  旧定时回调不会推进新一轮；断线重连后恢复当前对象与剩余倒计时；
- **议题投票卡**：主持人填写议题标题并选择 **15 秒～10 分钟**截止时长发起当前议题
  （发起新议题会立即结算旧议题，也可提前结束）；参与者（含主持人）在截止前对
  **赞成 / 反对 / 弃权** 投一票，**可随时改投**（每人一票，以最后一次为准）。
  页面实时显示三选项票数与占比、已投票人数、按服务端时钟同步的剩余倒计时；
  到期由服务端自动结算，结论为**通过 / 否决 / 平票**并保留在「已结算议题」列表。
  投票命令同时校验版本与 `topicId`，截止回调内再校验议题 id——
  **旧回调直接忽略，只结算当前议题**；断线重连后票数、剩余时间与结算结果连续恢复；
- **行动项看板**：主持人从**当前成员**中指定**负责人**，填写事项与**截止时间**创建行动项；
  负责人在线**接受 / 拒绝**，接受后可**标记完成**，主持人再**确认完成**或**退回处理中**。
  负责人可对待接受 / 处理中事项**申请延期**（新截止时间 + 理由），同一事项仅保留一条待审申请，
  主持人**批准 / 拒绝**：批准原子更新截止时间并标记已生效，拒绝保留理由；事项进入终态时
  未审结申请自动作废。看板按**待接受 / 处理中 / 待确认 / 已完成·已拒绝**四组展示，未完结项按
  截止时间排序并红色标注逾期；每项卡片展示**延期申请状态、理由、申请人/审批人**与最近状态变更记录
  （时间 + 操作者 + 动作）。全部流转复用版本守卫并**校验操作者身份与当前状态**——多端重复确认、
  越权跳转都会被拒绝并返回最新快照；断线重连后行动项状态完整恢复；
- **分组讨论面板**：主持人从**当前成员**中选取 **2～12 人**、设置 **2～4 个小组**
  （组数不超过人数，各组人数之差不超过 1），并可对所选成员对添加
  **必须同组 / 必须分开** 约束（同组关系按传递闭包生效）。服务端用完整回溯求解：
  方案覆盖全部所选成员且每人恰好出现一次、满足全部约束——**存在可行方案就必然找到**；
  无解时明确提示并**保留上次方案**，绝不忽略约束凑结果。方案随快照向全员展示并
  **保留生成时昵称**，成员进出不自动重分（已离开成员在方案中标注），断线重连可恢复；
- **现场问题墙**：当前成员可在房间页面提交**不超过 120 字**的现场问题，并对任意
  **未合并**问题点「👍 支持」切换支持状态（同一成员对同一问题只计一次，再次点击取消）。
  页面按**支持人数降序**展示未合并问题（同票按提交时间先后）。主持人可把一条问题
  **并入另一条未合并问题**：目标问题**合并两边支持者，同一成员只计一次**；来源问题
  随即**标明去向且不再接受支持**，底部「已合并问题」可查看其合并去向（沿合并链解析到
  最终目标）。主持人还可对一条**未合并、未结案**问题填写 **1～300 字答复并结案**：
  结案瞬间**固定该问题的支持人数、支持者及沿合并链归入它的全部来源问题**，记录答复人
  与时间；已结案问题连同答复在房间页「已结案问题与答复」区**单独展示**，已合并来源在
  其最终目标结案后仍可直接看到**最终答复**。提交、支持、合并、结案全部沿用现有
  WebSocket 身份与**版本守卫**——过期请求返回 `STALE_VERSION` + 最新快照，针对已合并
  问题的支持 / 合并 / 结案返回 `QUESTION_MERGED`，针对**已结案**问题的重复结案、支持、
  合并返回 `QUESTION_CLOSED`，空白答复返回 `NO_QUESTION_ANSWER`、超长答复返回
  `QUESTION_ANSWER_TOO_LONG`，均**不改变版本与记录**。问题、支持与答复随房间快照同步，
  断线重连后完整恢复；
- 主持人上述四类操作支持**安全撤销**：只回滚受影响的队列位置与当前发言，
  之后出现任何版本化变更即立即失效，撤销记录全程留下可见审计；
- 大屏展示当前发言人、大号**发言计时**、发言队列、在场成员与**操作记录**；
- 弱网/刷新/休眠后**自动断线重连**，恢复一致的队列顺序与当前发言计时；
- 所有队列命令携带客户端所见**版本号**，服务端**原子校验 + 单调递增**，
  过期命令被拒绝并返回最新快照，多端操作不会互相覆盖。

技术栈：Node.js + Express + ws（WebSocket），前端为原生 HTML / CSS / JavaScript，无构建步骤。

## 快速开始（Docker）

需要安装 Docker（含 Compose v2，即随 Docker Desktop 一起安装的 `docker compose` 插件；
Linux 单独安装时请确认 `docker compose version` 可正常输出）。

### 启动服务

在项目根目录（含 `compose.yaml` 与 `Dockerfile` 的目录）执行：

```bash
docker compose up --build
```

该命令会自动完成依赖安装（`npm ci`）、镜像构建并以前台方式启动服务，
看到 `发言席位服务已启动: http://localhost:3000` 即表示就绪。
启动后浏览器访问：

> **http://localhost:3000**

主持人打开页面 → 「创建房间」→ 把 6 位房间码（或「复制邀请链接」）投给参与者；
参与者打开同一地址输入房间码和昵称即可加入。

### 停止服务

- 前台运行时直接按 `Ctrl + C` 停止容器；如需连同容器一起移除：

```bash
docker compose down
```

### 后台运行 / 查看日志 / 重新构建

```bash
docker compose up --build -d   # 后台（detached）方式启动
docker compose ps              # 查看容器运行状态
docker compose logs -f         # 实时跟踪服务日志
docker compose restart         # 重启服务（不重新构建）
docker compose up --build -d   # 修改代码后重新构建并启动
docker compose down            # 停止并移除容器（镜像保留）
```

> compose 已配置 `restart: unless-stopped`：容器异常退出或宿主机重启后会自动拉起，
> 执行 `docker compose stop` 后才会保持停止。

### 使用其他宿主机端口

容器内固定监听 3000 端口，宿主机映射端口可用 `PORT` 变量覆盖（例如改用 8080）：

```bash
PORT=8080 docker compose up --build
```

然后访问 http://localhost:8080 。

> Windows PowerShell 下环境变量写法不同：
>
> ```powershell
> $env:PORT=8080; docker compose up --build
> ```

### 不使用 Compose：直接用 Docker 运行

```bash
docker build -t speak-queue:latest .
docker run --rm -p 3000:3000 --name speak-queue speak-queue:latest
```

自定义端口与配置（更多环境变量见下文「配置项」）：

```bash
docker run -d --name speak-queue \
  -p 8080:3000 \
  -e ROOM_TTL_MS=14400000 \
  -e LOG_LIMIT=500 \
  speak-queue:latest
```

健康检查：镜像内置 `/healthz` 探针（`http://localhost:3000/healthz` 返回
`{"ok":true,...}`），容器编排与外部探活均可直接使用。

## 配置项（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 服务监听端口。compose 中同时用它控制宿主机映射端口（`${PORT:-3000}:3000`） |
| `HOST` | `0.0.0.0` | 监听地址 |
| `WS_PATH` | `/ws` | WebSocket 挂载路径 |
| `ROOM_TTL_MS` | `14400000`（4 小时） | 房间内**所有人离线**后，房间保留多久再回收 |
| `LOG_LIMIT` | `500` | 服务端保留的操作记录最大条数（超出滚动淘汰） |
| `SWAP_RESOLVED_TTL_MS` | `30000`（30 秒） | 已结束的换位邀请（接受/拒绝/撤回/失效）在房间快照中继续保留的时长，供前端展示操作反馈 |
| `SPEAK_TIME_UNIT_MS` | `60000`（1 分钟） | 限时发言的时长单位（`durationMin` 乘数）。仅测试调小（如 `50`）以快速验证到期自动结束 |
| `QUOTA_TIME_UNIT_MS` | `60000`（1 分钟） | 累计发言配额的时长单位（`quota_reset` 的 `durationMin` 乘数）。仅测试调小（如 `50`）以快速验证额度耗尽自动结束 |
| `ROLLCALL_TIMEOUT_MS` | `20000`（20 秒） | 队首点名接力中每位成员的确认时限；超时自动移到队尾并点名下一人。测试调小（如 `800`） |
| `TOPIC_MIN_SECONDS` | `10` | 议题投票的截止时长下限（秒）。测试调小（如 `1`）以快速验证到期自动结算 |
| `TOPIC_MAX_SECONDS` | `3600`（60 分钟） | 议题投票的截止时长上限（秒） |
| `TOPIC_HISTORY_LIMIT` | `20` | 房间内保留的已结算议题数量（超出滚动淘汰，最新在前） |
| `TASK_HISTORY_LIMIT` | `20` | 每个行动项保留的最近状态变更记录条数 |
| `TASK_RESOLVED_LIMIT` | `50` | 房间内保留的已完结（已完成/已拒绝）行动项数量（超出滚动淘汰） |
| `TASK_MAX_OPEN` | `100` | 房间内未完结（待接受/处理中/待确认）行动项数量上限 |
| `QUESTION_MAX_OPEN` | `300` | 现场问题墙未合并且未结案问题数量上限（已合并 / 已结案问题随来源持续留存，不占此名额） |

compose.yaml 的 `environment` 段可直接修改容器内配置；宿主机端口可通过
`docker compose up --build` 前设置 `PORT` 环境变量覆盖。

## 使用说明

### 主持人（创建房间者）

- 页面会显示黄色「主持人」标识；创建信息保存在本浏览器，刷新/断线自动恢复主持身份。
- **拖动**队列条目前的 ⠿ 手柄即可调整发言顺序（鼠标与触屏均可）。
- 每条队列可点 **▶ 开始** 请其发言（自动从队列移除并开始计时），舞台区可随时**结束发言**。
- **📢 点名接力**：队列标题栏点「📢 点名接力」即从队首开始一轮点名（要求队列非空且当前无人发言）：
  - 服务端按队列顺序逐一点名，每位成员有 **20 秒**（`ROLLCALL_TIMEOUT_MS`）确认时间；
    队列上方会显示**当前对象、同步倒计时、本轮已点名人数**，被点到的成员本人会看到
    **✅ 我确认，开始发言** 与 **⏭ 跳过（移到队尾）** 两个按钮。
  - 成员**确认**：立即从队列移除并开始发言（接力结束）；成员**跳过**或**超时未操作**：
    自动移到队尾，服务端立即点名下一人；同一轮**每人最多被点名一次**，
    全员都跳过后本轮自动结束（队列保留跳过后的顺序）。
  - 主持人可随时点 **取消点名** 中止本轮（队列不变）；点名期间主持人直接
    **▶ 开始** 请任意成员发言，也会结束本轮点名。
  - 被点名人断线不影响服务端计时，其在倒计时内重连可继续确认/跳过；
    被点名人主动离开、取消申请或被主持人移出队列时，立即自动点名下一人。
  - 点名期间冻结换位与拖动排序（进行中的换位邀请会在点名启动时失效）；
    点名启动后新加入队列的成员排在本轮名单之后，下一轮再点。
- **限时发言**：队列标题栏的「限时」下拉框可选择 1～30 分钟时长（默认「不限时」），
  选择后开始的该轮发言进入倒计时：
  - 快照下发 `startedAt` / `endsAt` / `roundId`（唯一轮次标识），所有客户端按服务端
    时钟（`serverTs` 校准）显示同步倒计时，**最后 30 秒**倒计时变为红色闪烁提示。
  - 到期由**服务端自动结束**本轮：版本 +1、广播快照、写入「时间到，自动结束」操作记录，
    并按普通状态变更使挂起的安全撤销失效。
  - 手动结束、撤销开始、切换发言人、移出 / 离开 / 一键清空都会使旧定时任务立即失效；
    服务端回调内还会校验 `roundId`，旧回调不会结束后续轮次。
  - 撤销「结束发言」会连同 `endsAt` / `roundId` 一起恢复，倒计时继续（已到期则立即自动结束）。
  - 成员断线不影响进行中的轮次，重连后倒计时继续。
- **累计发言配额**：队列标题栏「配额」下拉框选择 1～30 分钟后点 **⏱ 开启发言配额**，
  即开始计费周期；开启后按钮变为 **🔁 重置配额周期**，再次点击（需确认）全员已用额度
  清零、周期标识更新，当前发言者从重置时刻起按新周期计费：
  - 队列上方配额条显示本周期每人额度、周期标识与你的实时余额；成员列表与队列条目
    同步显示每人余额，当前发言区显示发言人实时余额（≤30 秒红色醒目提示）。
  - 每轮发言结束时按**实际发言时长**扣减该成员余额；余额耗尽即**自动结束**其发言
    并写入 `quota` 操作记录，该成员本周期内**无法再次排队**，主持人也不能再请其发言
    （均返回 `QUOTA_EXHAUSTED`），界面各处标注「配额已用尽」。
  - 手动结束与到期回调竞争时只结算一次；旧周期的到期回调（携带旧 `periodId`）
    一律作废，不会扣减新周期。
- **安全撤销**：拖动排序、移出队列、开始 / 结束发言后，队列下方会出现绿色
  **可撤销**条，显示最近一次操作摘要（如「请『阿东』开始发言」），点 **↩ 撤销**
  可原子恢复受影响的队列位置与当前发言：
  - 仅允许撤销**最近一次**主持人操作；操作后只要出现**任一版本化状态变更**
    （成员加入 / 离开 / 断线、申请或取消发言、换位邀请变化、清空记录等），
    撤销条立即变为红色并展示**失效原因**，无法再撤销。
  - 撤销不会回滚成员在线状态、身份凭证或无关日志；恢复发言沿用原
    `startedAt`，发言计时连续不重置。
  - 每次成功撤销都会在操作记录中追加一条青色**审计记录**（`audit`）。
  - 版本冲突时 `undo_host` 同样返回 `STALE_VERSION` 与最新快照，客户端自动同步。
- **一键清空**：清空发言队列、结束当前发言并重置操作记录。
- 另有单独的**清空记录**按钮，只清空操作记录。
- **议题投票卡**：中部「🗳️ 议题投票」面板点 **＋ 发起议题**：
  - 填写议题标题，选择截止时长（15 / 30 秒，1 / 2 / 3 / 5 / 10 分钟），发布后开始投票；
    主持人本人同样可以投出一票。
  - 进行中议题会显示**实时票数**（赞成 / 反对 / 弃权的票数与占比）、**已投票人数**与
    **同步剩余时间**（最后 10 秒红色醒目提示）；每人**截止前可反复改投**。
  - 点 **⏹ 提前结束并结算** 立即结算；再次发起新议题时，旧议题会被**立即提前结算**
    （记录为「被新议题替换」），旧议题的定时回调不会影响新议题。
  - 到期由服务端自动结算：**赞成多于反对 = 通过**，反对多于赞成 = 否决，相等（含全弃权）
    = 平票；最近 20 条已结算议题保留在卡片底部，操作记录中留有完整结算日志。
  - 与限时发言一致：服务端定时回调内校验 `topicId`，主持人切换 / 结束议题时清理旧计时器，
    旧回调一律忽略。
- **行动项**：中部「✅ 行动项」面板点 **＋ 新建行动项**，从**当前成员**下拉框中选择
  **负责人**、填写事项内容并选择**截止时间**（默认 1 小时后）：
  - 看板按 **待接受 / 处理中 / 待确认 / 已完成·已拒绝** 四组展示；未完结项按截止时间
    升序排列，**逾期项红色标注**剩余时间；已完结组按最近更新排序。
  - 负责人标记完成后，行动项进入「待确认」组，主持人可 **✅ 确认完成**（进入已完成）
    或 **↩ 退回处理中**（打回给负责人继续处理）。
  - 负责人提交**延期申请**后，卡片显示橙色「延期待审批」区块（新截止时间、理由、申请人与时间），
    主持人可 **✅ 批准延期**（截止时间原子更新、申请标记已生效）或 **拒绝延期**（保留理由，
    截止时间不变）；事项确认完成 / 被拒绝时，未审结申请自动作废。
  - 每项卡片底部保留**最近一条状态变更记录**（时间 + 操作者 + 动作），完整记录随快照下发。
  - 一键清空**不会**清除行动项（行动项有独立的生命周期）。
- **分组讨论**：「🧩 分组讨论」面板点 **＋ 生成分组**：
  - 从**当前成员**中勾选 2～12 人（离线成员也可勾选），选择 2～4 个小组
    （组数不超过人数；表单实时提示每组人数分配，各组人数之差不超过 1）；
  - 可对所选成员对添加 **必须同组 / 必须分开** 约束（可多条、可删除）；
    同组关系按**传递闭包**生效（A 与 B 同组、B 与 C 同组 ⇒ A 必与 C 同组）；
  - 点 **生成方案** 后由服务端完整回溯求解：方案覆盖全部所选成员、每人恰好出现一次、
    满足全部约束；**存在可行方案就必然找到**。无解（如约束相互矛盾、同组块超过
    组规模上限）时明确提示原因并**保留上次方案**，不会忽略约束凑结果；
  - 再次打开表单会**自动沿用上次方案**的成员与约束（已离开成员自动剔除并提示），
    方便微调后重新生成；生成命令复用主持人权限与版本校验，过期或包含已离开成员的
    请求会被拒绝并返回最新快照。
- **现场问题墙**：中部「❓ 现场问题墙」面板，全员都可提交问题，主持人同样可以：
  - 每个成员都能在输入框提交**不超过 120 字**的问题，未合并、未结案问题按
    **支持人数从多到少**排列（同票按提交先后），前 3 名有金/银/铜色名次标注，适合投屏快速聚焦热点。
  - 点问题卡片上的 **👍 支持**即加入支持者（按钮变绿、计数 +1），**再次点击取消支持**；
    同一成员对同一问题只计一次。已离开成员的支持仍计入总数。
  - 主持人在每条未结案问题上点 **🔀 并入此条**，从弹窗列出的其他未结案问题中选择来源
    （输入序号）：确认后**两边支持者去重合并**，来源问题出现在底部「已合并问题」区并
    标明去向，**不再接受支持**；针对已合并问题的支持或合并都会被拒绝且计数不变。
  - 主持人点未结案问题上的 **✅ 答复结案**，在弹窗填写 **1～300 字**答复并确认：结案瞬间
    **固定该问题的支持人数与支持者**，并把**沿合并链归入它的来源问题**（直接 + 各级间接）
    一并记入答复记录，同时记录答复人与时间。已结案问题移到「已结案问题与答复」区单独展示，
    **此后不可再获支持或参与合并，也不能重复结案**；空白或超长答复会被明确拒绝且状态不变。
  - 「已合并问题」区中，若其最终目标已结案，会在来源条目内联展示**最终答复**与答复人/时间，
    沿合并链归入结案问题的来源都能据此找到最终答复。
  - 过期请求统一返回 `STALE_VERSION` 并自动同步最新快照；问题、支持与结案记录断线重连后恢复。

## 协议与一致性设计

所有消息均为 WebSocket 文本帧（JSON）。

**客户端 → 服务端**（除 `join` / `leave` 外均需带 `version`）：

```
{ "type": "request_speak",  "version": 12 }
{ "type": "cancel_speak",   "version": 12 }
{ "type": "swap_invite",    "version": 12, "participantId": "p_xxx" }
{ "type": "swap_accept",    "version": 12, "swapId": "sw_xxx" }
{ "type": "swap_reject",    "version": 12, "swapId": "sw_xxx" }
{ "type": "swap_cancel",    "version": 12, "swapId": "sw_xxx" }
{ "type": "start_speaking", "version": 12, "participantId": "p_xxx", "durationMin": 5 }  // 主持人；durationMin 可选，1~30 整数，缺省不限时
{ "type": "end_speaking",   "version": 12 }                             // 主持人
{ "type": "reorder",        "version": 12, "order": ["p_a", "p_b"] }    // 主持人
{ "type": "remove",         "version": 12, "participantId": "p_xxx" }   // 主持人
{ "type": "undo_host",      "version": 12 }                             // 主持人：安全撤销
{ "type": "clear",          "version": 12 }                             // 主持人
{ "type": "clear_logs",     "version": 12 }                             // 主持人
{ "type": "rollcall_start",  "version": 12 }                            // 主持人：启动队首点名接力
{ "type": "rollcall_confirm","version": 12, "callId": "cl_xxx" }        // 当前点名对象：确认并开始发言
{ "type": "rollcall_skip",   "version": 12, "callId": "cl_xxx" }        // 当前点名对象：跳过（移到队尾）
{ "type": "rollcall_cancel", "version": 12 }                            // 主持人：取消点名
{ "type": "topic_create", "version": 12, "title": "是否同意…", "durationSec": 60 }  // 主持人：发起当前议题
{ "type": "topic_end",    "version": 12 }                               // 主持人：提前结束并结算
{ "type": "topic_vote",   "version": 12, "topicId": "tp_xxx", "choice": "yes" }     // yes|no|abstain，截止前可改投
{ "type": "quota_reset",  "version": 12, "durationMin": 10 }            // 主持人：开启/重置发言配额周期（1~30 分钟）
{ "type": "task_create",  "version": 12, "participantId": "p_xxx", "title": "整理会议纪要", "deadline": 1726… }  // 主持人：创建行动项（deadline 为 ms 时间戳）
{ "type": "task_accept",  "version": 12, "taskId": "tk_xxx" }           // 负责人：接受（待接受 -> 处理中）
{ "type": "task_reject",  "version": 12, "taskId": "tk_xxx" }           // 负责人：拒绝（待接受 -> 已拒绝）
{ "type": "task_complete","version": 12, "taskId": "tk_xxx" }           // 负责人：标记完成（处理中 -> 待确认）
{ "type": "task_confirm", "version": 12, "taskId": "tk_xxx" }           // 主持人：确认完成（待确认 -> 已完成）
{ "type": "task_return",  "version": 12, "taskId": "tk_xxx" }           // 主持人：退回处理中（待确认 -> 处理中）
{ "type": "task_deadline_request", "version": 12, "taskId": "tk_xxx", "deadline": 1726…, "reason": "…" }  // 负责人：提交延期申请（待接受/处理中）
{ "type": "task_deadline_approve", "version": 12, "taskId": "tk_xxx" }  // 主持人：批准延期（原子更新截止时间）
{ "type": "task_deadline_reject",  "version": 12, "taskId": "tk_xxx" }  // 主持人：拒绝延期（保留理由）
{ "type": "group_generate", "version": 12, "memberIds": ["p_a","p_b","p_c"], "groupCount": 2,
  "constraints": [ { "a": "p_a", "b": "p_b", "type": "together" }, { "a": "p_a", "b": "p_c", "type": "apart" } ] }
                                                          // 主持人：生成分组讨论方案（2~12 人、2~4 组）
{ "type": "question_submit",  "version": 12, "text": "能否补充一下预算明细？" }   // 当前成员：提交现场问题（≤120 字）
{ "type": "question_support", "version": 12, "questionId": "q_xxx" }              // 当前成员：对未合并、未结案问题切换支持（再发一次取消）
{ "type": "question_merge",   "version": 12, "sourceId": "q_a", "targetId": "q_b" } // 主持人：q_a 并入未合并、未结案的 q_b
```

房间快照携带 `undo` 字段，描述最近一次主持人操作的可逆状态：

```
{
  "op": "start_speaking",     // reorder | remove | start_speaking | end_speaking
  "status": "available",      // available（可撤销）| invalid（已被介入变更作废）
  "version": 12,              // 撤销锚点：该操作提交后的版本；undo_host 必须携带此版本
  "ts": 1726…,
  "summary": "请「阿东」开始发言",  // 客户端直接展示的操作摘要
  "reason": null,             // invalid 时的机器可读失效原因
  "reasonText": null          // invalid 时的可读失效原因
}
```

- 只有 `reorder / remove / start_speaking / end_speaking` 四类主持人操作会武装
  逆操作；之后**任一**成功提交的版本化状态变更都会把 `undo.status` 置为
  `invalid` 并注明原因（`queue_changed / speaking_changed / presence_changed /
  swap_changed / cleared / logs_cleared / state_changed`）。
- `undo_host` 与普通命令一样经过版本守卫：版本不匹配返回
  `{ type:"error", code:"STALE_VERSION", snapshot:{…最新快照…} }`；
  无可撤销操作返回 `UNDO_NONE`，已失效返回 `UNDO_INVALIDATED`（均附最新快照）。
- 撤销原子恢复受影响的队列位置与当前发言（恢复发言沿用原 `startedAt`），
  **不**回滚成员在线状态、身份凭证或无关日志，仅追加一条 `kind:"audit"` 的
  可见审计记录；撤销本身也是一次版本化提交，撤销后 `undo` 为 `null`（不提供重做）。

换位邀请记录随房间快照的 `swaps` 字段广播：

```
{
  "id": "sw_…", "from": "p_a", "to": "p_b",
  "version": 12, "fromPos": 0, "toPos": 2,          // 发起时的队列版本与位置（0 基下标）
  "status": "pending",        // pending | accepted | rejected | cancelled | invalid
  "reason": null,             // 失效/结束原因，如 reordered、left、position_changed 等
  "ts": 1726…, "resolvedAt": null
}
```

- `swap_invite` 与普通队列命令一样严格校验版本；`swap_accept / swap_reject /
  swap_cancel` 只要求携带 `version`，不强制版本相等——接受的真正冲突以双方位置
  重新校验为准，队尾无关变动（版本增长但位置未变）不会使操作失败。
- 接受时若 `order[fromPos] === from && order[toPos] === to` 不成立，邀请置为
  `invalid`（`reason: "position_changed"`）且**队列保持不变**；校验通过则在同一
  次同步状态变更中交换两个下标。
- 一方取消申请、开始发言、被主持人移除、主动离开，或主持人重排 / 一键清空时，
  相关待处理邀请统一置为 `invalid` 并在操作记录注明原因（断线保留邀请，重连后可继续）。

限时发言轮次随房间快照的 `speaking` 字段广播：

```
{
  "id": "p_xxx", "nick": "阿东",
  "startedAt": 1726…,           // 服务端计时起点（用于已用时显示）
  "endsAt": 1726…,              // 限时时长到期点；不限时为 null
  "roundId": "rd_…"             // 唯一轮次标识，每轮发言都不同
}
```

- `start_speaking` 携带 `durationMin`（1～30 的整数，单位分钟）时开启限时；
  非法时长返回 `BAD_DURATION` 且不改变版本。服务端为每轮安排一个到期定时任务，
  到点执行自动结束：`version += 1`、广播快照、写入 `kind:"talk"` 的
  「时间到，自动结束」操作记录，并与普通状态变更一样使挂起的撤销失效
  （`undo.reason = "speaking_changed"`）。
- 手动结束、撤销开始、切换发言人、移出 / 离开 / 一键清空都会先 `clearTimeout`
  使旧定时任务失效；定时回调触发时还会校验 `roundId` 是否仍为当前轮次，
  旧轮次的回调不会结束后续轮次。
- 客户端用快照 `serverTs` 校准本机时钟后，按 `endsAt` 渲染同步倒计时，
  剩余 ≤ 30 秒时醒目提示；断线重连后重新收到快照，倒计时继续。

累计发言配额随房间快照的 `quota` 字段广播（未开启时为 `null`）：

```
{
  "periodId": "qp_…",            // 本周期唯一标识（每次开启/重置都更换）
  "limitMs": 600000,             // 每人配额毫秒数（1～30 分钟）
  "startedAt": 1726…,            // 周期开启时间（ms）
  "members": {                   // 以参与者 id 为键的余额表
    "p_a": { "usedMs": 123000, "remainingMs": 477000 }
  }
}
```

- `quota_reset` 仅主持人可发；`durationMin` 须为 1～30 的整数（非法返回
  `BAD_DURATION`），命令走版本守卫（过期返回 `STALE_VERSION`）。每次重置都
  产生新的 `periodId` 并将全员已用额度清零；当前发言者从重置时刻起计入新周期。
- 服务端在每轮发言结束时按**实际发言时长**结算扣减（封顶 `limitMs`）；
  手动结束与配额到期回调竞争时，`roundId` 守卫保证本轮只结算一次。
- 发言人余额耗尽时，服务端自动结束本轮（`version += 1`、广播快照、写入
  `kind:"quota"` 的操作记录，并使挂起的安全撤销失效）；余额为 0 的成员
  `request_speak` / 被 `start_speaking` / `rollcall_confirm` 均返回
  `QUOTA_EXHAUSTED`（附最新快照，不改变版本）。
- 配额到期回调携带 `periodId + roundId` 双重校验：重置周期或轮次结束后，
  旧回调一律作废，**不会扣减新周期**。
- 快照中当前发言者的 `usedMs` 含本轮未结算的实时时长；客户端按 `serverTs`
  校准时钟后继续递减 `remainingMs` 即可显示实时余额，断线重连后凭快照恢复真实余额。

```
  "history": [             // 最近状态变更记录（最多 TASK_HISTORY_LIMIT 条）
```

- 状态机：`pending → active → review → done`；`pending` 可被负责人拒绝为 `rejected`；
  `review` 可被主持人退回 `active`。`done` / `rejected` 为终态，其余跳转一律拒绝。
- **延期申请**：负责人可对 `pending` / `active` 事项提交 `task_deadline_request`
  （新截止时间须为**将来一年内且晚于当前截止时间**，理由不能为空）；同一事项已有待审申请
  返回 `TASK_REQUEST_PENDING`，新申请会覆盖上一条**已审结**申请。主持人对非待审申请批准 /
  拒绝返回 `TASK_REQUEST_NONE`；批准在同一次同步变更中把 `deadline` 原子更新为申请值并把
  申请标记为 `approved`（已生效），拒绝置为 `rejected` 且截止时间不变、理由完整保留。
  事项进入终态（确认完成 / 负责人拒绝事项）时，仍待审的申请自动置为 `voided`
  （`decidedBy` 记录触发终态的操作者）；进入 / 退回 `review` 不影响申请。
- 全部命令严格校验 `version`（过期返回 `STALE_VERSION` + 最新快照）；负责人命令校验
  `assigneeId === 发送者`（否则 `TASK_NOT_YOURS`），主持人命令校验主持身份（否则
  `FORBIDDEN`）；当前状态不允许该流转时返回 `BAD_TASK_STATE` + 最新快照——
  多端重复确认、越权跳转都不会改变状态与版本。
- `task_create` 的 `deadline` 为 ms 时间戳，须为将来时间（容忍 5 分钟客户端时钟偏差）
  且不超过 366 天，非法返回 `BAD_DEADLINE`；负责人须为当前房间成员（否则
  `NO_PARTICIPANT`）；未完结行动项达到 `TASK_MAX_OPEN` 返回 `TASK_LIMIT`。
- 每个行动项保留最近 `TASK_HISTORY_LIMIT` 条状态变更记录随快照下发；已完结行动项
  仅保留最近 `TASK_RESOLVED_LIMIT` 条（滚动淘汰）。行动项变更同样使挂起的安全撤销
  失效（`undo.reason = "task_changed"`）。行动项无定时任务，断线重连后凭快照完整恢复。

- `question_submit` 任何当前成员（含主持人）均可发送；`text` 去空白后不能为空且

  `QUESTION_MAX_OPEN`（默认 300，已合并 / 已结案问题不占名额）返回 `QUESTION_LIMIT`，
  均不改变版本。
- `question_support` **同时校验 `version` 与问题状态**：版本不符返回 `STALE_VERSION`，
  问题不存在返回 `NO_QUESTION`，问题已合并返回 `QUESTION_MERGED`，问题已结案返回
  `QUESTION_CLOSED`——均附最新快照且**不改变计数 / 版本**。支持是**切换**语义：
  同一成员首次发送加入支持者集合，再次发送退出，计数以集合大小为准（天然每人只计一次）。
- `question_merge` 仅主持人可发（否则 `FORBIDDEN`），走版本守卫；来源 / 目标任一不
  存在返回 `NO_QUESTION`，来源与目标相同返回 `QUESTION_BAD_TARGET`，**来源或目标任一
  已合并都返回 `QUESTION_MERGED`、任一已结案都返回 `QUESTION_CLOSED`** 且计数不变。
  校验通过后，来源支持者按成员去重并入目标（同一次同步变更内完成），来源标记
  `mergedInto / mergedAt / mergedBy`，此后不再接受支持。合并可链式发生（目标之后也
  可能被并入其他问题），快照中的 `mergedRootId` 沿合并链解析到最终目标；最终目标结案后
  来源条目的 `rootClosed/rootAnswer` 等字段即指向该条最终答复。
- `question_close` 仅主持人可发（否则 `FORBIDDEN`），走版本守卫；问题不存在返回
  `NO_QUESTION`，问题已合并（来源不能单独结案）返回 `QUESTION_MERGED`，已结案返回
  `QUESTION_CLOSED`。`answer` 去空白后必须为 **1～300 字**：空白返回
  `NO_QUESTION_ANSWER`，超过 300 字返回 `QUESTION_ANSWER_TOO_LONG`（**不截断**），

  - 固定结案瞬间的支持人数与支持者（昵称一并留存为 `answerSupporters`），记录答复
    正文、答复人（`answeredBy/answeredByNick`）与 `closedAt`；
  - 把沿合并链归入该问题的**全部来源**（直接来源 + 各级间接来源，按合并时间升序）
    快照进 `answerSources`，每条带来源正文、作者、合并去向 / 终点、合并时间 / 操作者
    与该来源被合并时固定的支持者；
  - 问题移入 `closed`，此后针对它的支持 / 合并 / 重复结案一律返回 `QUESTION_CLOSED`，
    支持人数、支持者与来源快照不再变化。
- 问题、支持与答复记录保存在房间状态中、随每次快照广播；无定时任务，断线重连后凭
  快照完整恢复（成员离开不清问题、不清支持计数；结案记录中的昵称按结案时留存）。
  问题墙变更同样使挂起的安全撤销失效（`undo.reason = "question_changed"`）。

- 服务端在 Node 单事件循环中**同步**处理每条命令：校验 `version === 当前版本`
  后立即修改状态、`version += 1`，并向房间内所有连接广播快照——整个过程不可被其他命令插入。
- 版本不匹配时返回 `{ type:"error", code:"STALE_VERSION", snapshot:{…最新快照…} }`，
  客户端用其覆盖本地状态后再渲染，杜绝过期覆盖。
- 每次快照附带 `serverTs`，客户端据此修正本机时钟偏差，发言计时基于服务端的
  `speaking.startedAt`，重连后计时连续不重置。
- 断线不会立即删除席位：成员标记为离线、队列位置与当前发言均保留；
  参与者凭 `participantId + secret`、主持人凭 `hostToken` 重连恢复。

完整消息清单见 `server.js` 顶部注释，行为用例见 `test-e2e.js`。

## 说明 / 限制

- 房间状态保存在**内存**中（适合一次线下会议场景）：进程重启或房间超过
  `ROOM_TTL_MS` 无人在线后数据清除；无外部数据库依赖。
- 主持人能力由服务端通过 `hostToken` 校验，令牌仅保存在创建者浏览器的 localStorage 中。
